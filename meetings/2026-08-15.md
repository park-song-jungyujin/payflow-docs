- **팀 규모 및 법인 형태:** 5~20인 규모의 초기 스타트업, 개인사업자, 또는 대학생 프로젝트/동아리 팀

  - 법인카드 한도 부족으로 인한 개인 카드 선결제 정산 피로도

        사진이 맞는지만 확인. 올린 사진에 있던 비용이 영수증에 없으면 문제 제기

    - 입금 확인 — PayPal API. 에이전트가 무엇이 지급되고 거부됐는지 정리해서 보고
    - ~~청구 누락 방지~~ : 보류 (기술적 어려움)

1. **트리거**

   - **계정과목 자동 매핑:** "AWS 결제"를 `지급수수료`로, "팀 회식"을 `복리후생비`로 자동 분류

## 7. MVP 범위 및 데모 준비

**Must-Have (1차 구현 범위)**

- 슬랙 영수증 이미지 → Gemini 멀티모달 파싱 → 청구 항목 생성
- PayPal 결제 원장 ↔ 청구 항목 양방향 대조
- 미청구 건 자동 감지 → 슬랙 DM 발송 → 응답 대기 → 무응답 시 1회 재촉 → 버튼 응답 처리
- 이상 탐지: 유사 중복 청구 1건 + 영수증-청구 금액 불일치 1건
- 승인 게이트: 승인 토큰 없이는 송금 엔드포인트 호출 불가
- PayPal Sandbox Payouts 일괄 송금
- 지급 결과 대조 → 실패/UNCLAIMED 건 감지 → 취소 후 올바른 주소로 재발송 제안
- 세무사 전달용 XLSX 출력
- 감사 로그: 에이전트 판단 근거 및 도구 호출 이력 저장

**Won't-Have (Phase 2)**

Google Drive 자동 수집, 청구자용 별도 웹페이지, 계약서 단가 대조, 사업자등록번호 추출,
부가세 공제 판단, 타임시트 분석, Notion 연동, 5년 아카이빙 정책

**데모용 데이터셋**

- 정상 프리랜서 인보이스 2건
- 고의 중복 인보이스 1건 (이상 탐지 시연)
- 영수증 이미지와 청구 금액이 어긋나는 건 1건 (판단 시연)
- PayPal 결제는 있으나 영수증 미제출 건 1건 (추적 루프 시연)
- 미등록 이메일 수취인 1명 (UNCLAIMED → 취소 → 재발송 시연)
- PayPal Sandbox 비즈니스 발신 계정 1개 + 수신 가상 계정 3개

**데모 성립 조건**

- 시계 주입 설계: 며칠간의 대기를 40초로 압축 재생하되, 동일 코드가 실제 시계로
  GCP에서 실행된 로그를 병행 제시
- 승인 토큰 없이 송금 엔드포인트 호출 시 거부되는 장면 5초 확보

### CASE 정리

Agent가 영수증을 썼는데 틀렸으면 다시 써오라 하기. Agent가 다시 봤을 때 낸 사람이
잘못 낸 것 같으면 그 사람에게 다시 요청.

HIL 빠져나올 때까지 loop 반복.

Agent가 청구자에게 재요청하는 경우 — 뭘 잘못 낸 것 같을 때, OCR 실패했을 때.

미제출 항목에 대해 "이거 네가 긁지 않았음?" 확인.

미제출해서 기간 지난 건은 오프라인에서 처리.

# 부록 — 현재 문서와의 대조

## 규칙이 덮어쓴 것

회의록은 **"에이전트가 다 한다"**는 그림이고, 현재 규칙은 에이전트를 판단·서술 역할로
좁혔다. 아래는 **회의록이 낡은 쪽**이다.

| 회의록 | 현재 |
|---|---|
| 3.1 "영수증을 보내면 바로바로 **에이전트 호출**해서 JSON 저장" | 파싱은 `api`의 Gemini 단발 호출. ADK 아님 |
| 2 "에이전트가 파싱하여 **해당 결제 건과 자동 매칭**" | 매칭은 **결정론적 코드** |
| 1 "회계(agent)가 보고 **인보이스를 작성**해" | 금액 계산은 LLM이 하지 않는다 (절대 규칙 3) |
| 7 "**시계 주입 설계**" | 별도 가짜 시계 추상화를 만들지 않는다. `REMINDER_DELAY_SECONDS` 하나 |
| 2·5 "슬랙/**디스코드**" | Slack만. backend 시크릿은 `PayPal, Slack` |
| 5 Gemini 3.5 + ADK 단일 | 에이전트 **3개** — 청구자 · 집행자 · 안전 확인 |

## 회의록 내부 모순

본문에서 MVP 로직으로 서술한 걸 같은 문서 7번 Won't-Have가 제외했다.
**Won't-Have 쪽이 맞다.**

Google Drive 자동 수집 · 사업자등록번호/부가세 추출 · 계약서 단가 대조 ·
타임시트 분석 · 5년 아카이빙 · 청구자용 페이팔 연동 페이지

## 회의록에서 살린 것

| 항목 | 반영 |
|---|---|
| 계정과목 자동 매핑 | **MVP 포함.** 파싱 호출에 통합, 신뢰도 낮으면 `미분류` |
| 집행자 자연어 라우팅 | **MVP 포함.** 단 `SettlementFilter` 변환으로 범위 한정 |
| "10개 중 8개만 지급" 문제 제기 | 청구자 지급 결과 통지로 Track A에 배정 |

## 해소된 질문

**"줬다 뺏기 가능?"** — PayPal Payouts는 `UNCLAIMED` 상태에서만 취소된다.
수취인이 이미 수령한 건은 API로 회수할 수 없다. 상세는
[`../rules/money-safety.md`](../rules/money-safety.md).

## 모순이 아닌 것

"청구 누락 방지 보류"와 Must-Have "미청구 건 자동 감지"는 충돌하지 않는다. 전자는
원장에 흔적이 없는 오프라인 현금 지출, 후자는 PayPal 원장에 있는 건이다.
