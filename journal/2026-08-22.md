### 6. 멀티테넌시 구현 — backend `src/auth/` + frontend Google 로그인

**backend** (`feat/multi-tenant-auth` 브랜치): `src/auth/` 신설(google_oauth·
slack_oauth·session·store·routes) — 세션은 `guards/tokens.py` 승인 토큰과 같은
sha256 해시 저장 패턴. `guards/routes.py`의 승인 라우트가 `body.approved_by`를
그대로 신뢰하던 구멍(`demo_approver` 기본값)을 세션 검증 신원으로 교체하고
run의 `org_id` 소유권 확인 추가. `ingest/`가 Slack 이벤트의 `team_id`로
`slack_workspaces`를 조회해 `org_id`를 해석하고, 미등록 청구자를 초대 절차
없이 최초 메시지 시점에 자동 등록(lazy registration)하도록 교체 —
`unregistered_user` 무시 분기 제거. `parsing/slack_files.py`는 전역
`SLACK_BOT_TOKEN` 대신 org별 bot_token 조회로 전환. `settlements`·`payouts`
조회·생성 경로에 `org_id` 스코핑 추가, 다른 기관 run 접근 시 404로 존재
자체를 숨김. 기존 테스트 전체(guards·settlements·ingest·parsing·matching)를
새 시그니처에 맞춰 갱신, OpenAPI 스냅샷 재생성. 신규 `tests/auth/` 7개 포함
392개 전부 통과.

**frontend** (`feat/multi-tenant-auth` 브랜치): `src/app/login/` Google OAuth
리다이렉트(가입 시 기관명 입력) + `api/auth/google/callback` route handler가
코드를 backend로 넘기고 세션을 httpOnly 쿠키로 저장(승인 토큰과 같은
브라우저-비노출 패턴). `src/proxy.ts` 신설(Next 16에서 `middleware.ts`가
deprecated로 바뀌어 `proxy.ts`로 명명) — 세션 없으면 `/login` 리다이렉트.
기존 BFF 프록시 6곳 전부 세션 쿠키를 `Authorization` 헤더로 forward.
`next/headers`가 유닛 테스트의 요청 스코프 밖 호출에서 예외를 던지는 문제를
발견해 route handler는 `NextRequest.cookies`를 직접 쓰도록 분리. 기존
vitest 스위트가 `@/*` 별칭 테스트를 한 번도 안 거쳐 별칭 미설정 상태였던
것도 함께 발견해 `vitest.config.mts` 신설. typecheck·lint·test·build 전부 통과.

세 레포 모두 `feat/multi-tenant-auth` 브랜치에 커밋 완료, PR은 다음 단계.
Slack 앱·Google OAuth 클라이언트 실제 등록은 로컬에서 할 수 없는 수동
선행 작업으로 남음.
