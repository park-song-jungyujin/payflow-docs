### 5. 승인 토큰 403 게이트 실장 (같은 브랜치)

`plan.md` Phase 1 우선순위 3 — "승인 토큰 없이 `/payouts` → 403". schema-contract.md
§7 흐름과 money-safety.md 승인 게이트 규칙을 그대로 구현했다.

- `src/guards/tokens.py` — `approval_amount_hash`(발급·검증 공용, canonical JSON
  sha256), `issue_token`(원문은 반환값으로만, 저장은 해시), `verify_and_burn_token`
  (헤더 없음 → 403, CAS 상태 아님 → 409, 소각됨/만료/해시 불일치/캡 초과 → 403,
  성공 시 `APPROVED → EXECUTING` 전이 + `approval_token_used_at` 기록)
- `src/guards/limits.py` — 캡 3종(`MAX_AMOUNT_PER_{ITEM,BATCH,MONTHLY}_MINOR`)을
  환경변수에서 읽어 검사. 값 없는 캡은 건너뛴다
- `src/guards/audit.py` — 게이트 판단마다 `audit_logs` 스키마 그대로 인메모리 append
- `src/guards/routes.py`의 approve가 DRAFT→APPROVED CAS(상태 아니면 409) + 캡 검사
  (403) 후 토큰 발급
- `backend/.env`의 캡 3종에 fixture 7번 예시값(3,000,000 / 5,000,000 / 10,000,000)을
  채워 넣어 실제로 403이 재현되게 함

TestClient로 8가지 경로 확인: 토큰 없음(403) · 캡 초과 approve(403) · 정상 승인(200,
`approval_token_hash`는 응답에서 제외) · 잘못된 토큰(403) · 정상 토큰(200,
`EXECUTING`) · 같은 토큰 재사용(409, 상태가 이미 EXECUTING으로 바뀌어 CAS가 먼저
막음) · 이미 EXECUTING인 run 재승인 시도(409).

`uv add --dev httpx`가 `pyproject.toml`을 건드려 원복했고, 생성된 `uv.lock`은 커밋
대상에서 뺐다 (레포에 아직 lock 파일 관례가 없어 이번 스텁 작업 범위 밖으로 판단).

### 6. `sender_item_id` 길이 초과 — 축약형 채택으로 해소

8/16 journal(14번)·`plan.md`·`README.md`에 미해결로 남아 있던 항목. `settlement_run_id`를
전체 ULID로 쓰면 `sender_item_id`(`{run_id}:{recipient_id}`)가 70자로 PayPal 상한 63자를
넘는다. `settlement_run_id`를 축약형(`run_{yymmdd}_{ULID 앞 12자}`, 23자)만 쓰기로
정해 `sender_item_id`를 54자(재발송 57자)로 줄였다.

- `rules/schema-contract.md` §2(`settlement_runs.settlement_run_id`)·§3(ID 체계, PayPal
  연동 ID 절)을 축약형으로 갱신, "D2 관통 시 실측" 조건문을 확정 문구로 교체
- `plan.md`·`README.md`의 미결 목록에서 이 항목 제거, `확정된 것`에 추가
- `backend/tests/fixtures/`의 `settlement_run_id`(및 파생되는 `sender_item_id`,
  `sender_batch_id`, `agent_drafts.target_id`, 요청 `path`)를 5개 파일에 걸쳐 축약형으로
  전부 치환 — `01`, `03`, `07`(서브케이스 2개), `08`. fixture 8번의 `sender_item_id`가
  실제로 51자로 줄어든 것까지 확인
- 코드 쪽은 손댈 게 없었다 — ID를 실제로 생성하는 코드가 아직 없고, `guards`/`payouts`
  스텁은 fixture에 있는 ID를 그대로 조회만 한다

전부 `python -m json.tool`로 재검증, `feat/guards-payouts-stub` 브랜치에서 approve→payouts
흐름을 축약형 ID로 다시 스모크 테스트해 통과 확인.
