### 4. submodule 연결 및 레포별 `CLAUDE.md`

코드 레포 3개에 `payflow-docs`를 `docs/` submodule로 붙이고, 각 레포 루트에 얇은
`CLAUDE.md`를 두어 `@docs/CLAUDE.md`를 참조하게 했다. 레포별 책임과 금지사항만
자기 파일에 적었다.

워크스페이스 루트(`payflow/`)에도 `CLAUDE.md`를 두었다. 이 폴더는 git 레포가 아니므로
추적되지 않는다.

### 5. 마크다운 200줄 제한 폐지

"모든 마크다운은 200줄을 넘기지 않는다" 규칙을 `CLAUDE.md`에만 적용하도록 좁혔다.

폐지 근거:

- **줄 수가 크기를 반영하지 못한다.** `about_hackathon.md`는 줄 수로 `README.md`의
  4배지만 문자 수로는 1.8배다 (22자/줄 vs 50자/줄). 같은 "200줄 준수" 안에서도
  실제 분량이 2.3배 차이 난다.
- **우회가 쉽다.** README를 218→197줄로 줄일 때 한 편집 중 하나가 구분선 `---` 6개
  삭제였다. 내용은 그대로고 가독성만 나빠졌다.
- **처방이 문제를 키운다.** `원본-1.md`, `원본-2.md`는 주제가 아니라 크기로 자르므로
  이름이 정보를 담지 못하고, 에이전트는 포인터 파일 + 조각 N개를 읽어야 해서
  컨텍스트를 아끼려는 규칙이 컨텍스트를 더 쓴다.
- 규칙 도입 당일 `about_hackathon.md`(799줄)가 이미 위반 상태였다.

`CLAUDE.md`에만 제한을 남긴 이유는 이 파일만 매 세션 자동 로드되어 분량이 곧
반복 비용이기 때문이다. `rules/` 5종이 32~87줄에 안착한 건 제한 때문이 아니라
주제 하나씩 담았기 때문이므로, 규칙도 "크기가 아니라 주제로 나눈다"로 바꿨다.

docs 커밋 후 코드 레포 3개의 submodule 포인터도 함께 올렸다. 포인터가 뒤처지면
레포들이 옛 `CLAUDE.md`를 계속 읽는다.
