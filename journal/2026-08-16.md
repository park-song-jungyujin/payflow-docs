### 5. 마크다운 200줄 제한 폐지

"모든 마크다운은 200줄을 넘기지 않는다" 규칙을 `CLAUDE.md`에만 적용하도록 좁혔다.

폐지 근거:

- **줄 수가 크기를 반영하지 못한다.** `about_hackathon.md`는 줄 수로 `README.md`의
  4배지만 문자 수로는 1.8배다 (22자/줄 vs 50자/줄). 같은 "200줄 준수" 안에서도
  실제 분량이 2.3배 차이 난다.
- **우회가 쉽다.** README를 218→197줄로 줄일 때 한 편집 중 하나가 구분선 `---` 6개
  삭제였다. 내용은 그대로고 가독성만 나빠졌다.
- **처방이 문제를 키운다.** `원본-1.md`, `원본-2.md`는 주제가 아니라 크기로 자르므로
  이름이 정보를 담지 못하고, 에이전트는 포인터 파일 + 조각 N개를 읽어야 해서
  컨텍스트를 아끼려는 규칙이 컨텍스트를 더 쓴다.
- 규칙 도입 당일 `about_hackathon.md`(799줄)가 이미 위반 상태였다.

`CLAUDE.md`에만 제한을 남긴 이유는 이 파일만 매 세션 자동 로드되어 분량이 곧
반복 비용이기 때문이다. `rules/` 5종이 32~87줄에 안착한 건 제한 때문이 아니라
주제 하나씩 담았기 때문이므로, 규칙도 "크기가 아니라 주제로 나눈다"로 바꿨다.

docs 커밋 후 코드 레포 3개의 submodule 포인터도 함께 올렸다. 포인터가 뒤처지면
레포들이 옛 `CLAUDE.md`를 계속 읽는다.

### 6. 구현 계획 작성 (`plan.md`)

3인 병렬 작업 계획을 작성했다. 마감까지 16일, 풀타임 3인 전제.

**에이전트를 3개로 나누기로 결정했다** — 청구자용 / 집행자용 / 안전 확인.
트랙 경계와 1:1로 맞춰 각자 자기 에이전트를 끝까지 소유한다.

이 결정은 현재 규칙과 충돌하므로 D1에 아래를 함께 고쳐야 한다.

| 파일 | 변경 |

| `payflow-agent/CLAUDE.md` | 하지 말 것 "멀티 에이전트" 삭제 |

`CLAUDE.md` 절대 규칙 3개와 `money-safety.md`는 바꾸지 않는다. 에이전트를 늘리는 것과
돈 규칙을 푸는 것은 별개다.

설계상 못박은 것 둘:

- **에이전트끼리 직접 호출하지 않는다.** 셋 다 `api`가 파이프라인 단계마다 Cloud Tasks로
  부르고 결과는 Firestore draft로만 돌려준다. 에이전트 간 프로토콜을 만들면 통합
  비용이 감당이 안 된다.
- **안전 확인 에이전트는 게이트가 아니라 조언자다.** 실제 차단(한도·토큰·CAS·중복)은
  전부 코드가 한다. LLM을 게이트로 두면 인젝션된 영수증이 승인을 통과시킬 수 있고,
  에이전트 출력이 비어도 코드 게이트는 독립적으로 동작해야 한다.

병렬화는 계약 우선 + 스텁으로 푼다. `schema-contract.md`의 `api → agent → web` 순서를
그대로 따르면 두 사람이 대기하므로, D1에 구현 없이 스키마만 확정해 태그를 끊고
D2에 fixture 반환 스텁을 배포한 뒤 D3부터 완전 병렬로 간다. 세 트랙이 모두
`payflow-backend`를 건드리므로 디렉터리 소유권도 미리 갈랐다.

### 8. 스캐폴딩 생략 결정 및 진행 현황 표시

**별도 스캐폴딩 단계를 두지 않기로 했다.** 각 트랙이 D1~D2에 자기 레포를 직접 세운다.
