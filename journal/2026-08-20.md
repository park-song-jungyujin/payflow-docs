## 진행 내역

### 1. `track-status-diagrams.html`, `workflow-diagrams.html` 다이어그램 가로 배치

`.diagram-grid`로 `<section>`을 감싸 그리드 배치. `workflow-diagrams.html`(다이어그램 2개)은 2열, `track-status-diagrams.html`(다이어그램 3개)은 3열로 한 행에 나열. 그리드 아이템이 mermaid SVG 너비만큼 늘어나 컬럼 폭이 어긋나던 문제는 `section { min-width: 0 }`로 해결.

### 2. `track-status-diagrams.html` 섹션 제목 줄바꿈 방지

`section h2` 폰트 크기 축소 + `white-space: nowrap` + `text-overflow: ellipsis`, `.badge`에 `flex-shrink: 0` 적용.

### 3. `cicd-infra-diagrams.html` 신설

`backend/.github/workflows/deploy.yml`, `agent/.github/workflows/deploy.yml`, `frontend/.github/workflows/deploy.yml`, `backend/infra/*.tf`를 직접 읽어 push → GitHub Actions(레포별 WIF) → Cloud Run 3서비스 배포 → Cloud Tasks/Firestore/GCS/Secret Manager/Vertex AI 연결 → 청구자(Slack)/집행자(브라우저) 접점까지 단일 mermaid 다이어그램으로 정리. 구현 완료(초록)/부분 구현(주황, 테스트 게이트 없는 backend·agent CI)/미구현(회색, `payflow-api`의 Gemini 파싱 경로) 색상 구분 포함.

### 4. `payflow-backend` CI에 pytest 게이트 추가, money-safety 핵심 로직 단위 테스트

`deploy.yml`에 `test` job(`uv sync` → `uv run pytest`) 신설, `deploy` job에 `needs: test` 적용.

`tests/payouts/test_idempotency.py` — `build_payout_ids` 재시도 시 결정론적 ID 생성 5종.
`tests/guards/test_tokens.py` — `verify_and_burn_token` 토큰 누락/위조/재사용/만료, 상태
불일치, amount_hash 불일치, 한도 위반, CAS 재확인(스테일 run dict) 9종.
`tests/guards/test_limits.py` — `check_caps` 배치/항목/월간 캡, FX 환산 경유 초과 판정 7종.

`scripts/test_payout_idempotency.py`(라이브 PayPal sandbox 호출)는 CI에 못 넣어 수동
검증용으로 남김.

### 5. `payflow-agent` 테스트 인프라 신설(pytest 부재였음)

`pyproject.toml`에 pytest dev 의존성 + `testpaths` 추가. `deploy.yml`에 `test` job
신설, `deploy` job에 `needs: test` 적용.

`tests/test_{claimant,executor,safety}_tools.py` — 에이전트 툴별 빈 입력 거부,
`write_agent_draft` 호출 인자 형태 검증.
`tests/test_api_client.py` — `shared/api_client.py` 요청 URL/헤더/바디, base URL
trailing slash 처리, HTTP 에러 전파.
`tests/test_callbacks.py` — `before_tool_callback` 세션당 호출 횟수 카운팅, 한도 초과 시
거부(예외 아님), 거부/허용 각각의 감사 로그 액션.
`tests/test_memory.py` — `shared/memory.py`(agent_sessions) 세션 생성/재사용, 턴 추가,
세션 종료 요약(금액 미포함 확인), 이전 세션 조회(자기 자신 제외, CLOSED만).
`tests/test_schema_contract.py` — pin된 `payflow-backend`의 `AgentName`/
`AgentDraftTargetType` enum이 `before_tool_callback` 하드코딩 값·툴 호출 인자와
일치하는지, 각 툴의 draft 페이로드가 `AgentDraft` 스키마로 검증되는지 확인.
`tests/test_main.py` — FastAPI 라우트(OIDC 401, claimant/executor 501, 필드 누락 400) +
`_run_once`(ADK Runner)만 스텁 처리한 파이프라인 테스트로 OIDC → before_tool_callback →
submit_risk_report → draft 기록까지 전체 체인 검증.

claimant/executor 실제 분류/분석 로직(Track A/B)은 아직 baseline(submit_*)만 커버 —
로직 채워지면 테스트 추가 필요.
